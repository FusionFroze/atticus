2. **`src/core/time.ts`**: the most recent scheduled moment at or before now for (`DIGEST_DAY`, `DIGEST_HOUR`, `TIMEZONE`), using `Intl.DateTimeFormat` (V71). Unit tests: `Asia/Kolkata` (no DST), `America/New_York` and `Europe/London` across both DST changes, a run at exactly the hour, a run 23 h 59 min late (sent), 24 h late (skipped), the week boundary at midnight.
3. **`src/core/digest.ts`**: pure stats from rows: counts of new and edited, average written rating and the change from the previous week, the 1–5 distribution, the reply rate, the median time to reply (bot replies only, `first_seen_at` → `replied_at`), the breakdown by app version, the three lowest-rated unanswered reviews. Unit tests for each figure, empty weeks, one review, ties.
4. **`src/store/`**: the digest queries (the two weeks' rows for an app), plus the links to each review's latest message.
5. **`src/jobs/digest.ts`**: V71's check; enqueue the digest outbox row(s) and set `digest_last` in one batch. Skipped when `DIGEST_ENABLED=false`.
6. **Rendering**: the digest message, iterated with the user in the test channel (V81); "written reviews only" always visible (Copy). Confirm the v1-6 Copy rows and mark them locked.
7. **Integration tests:** due → enqueued once, not again in the same week; late by more than a day → skipped and logged; disabled → nothing; the digest sent through the outbox like any other kind.
