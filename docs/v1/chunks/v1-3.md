## In

1. **`src/notifiers/types.ts`**: the `Notifier` contract. Lock its method list.
2. **`src/notifiers/discord/client.ts`**: REST v10 with the bot token and V44's `User-Agent`. `POST` with `nonce` and `enforce_nonce`, `PATCH`, `allowed_mentions` on every call (V43). `429`: read `retry_after`; if it's under 2 s and the budget allows, wait and retry once, otherwise return `rate_limited`. Map statuses to `SendFailure`. Every call takes from the `Budget`. Never log the token or a response body.
3. **`src/notifiers/discord/render.ts`**: pure builders from domain data to message payloads: the review message (both formats while iterating, see 5), the Connected notice, the low-rating mention (V43), the buttons (V42: Reply with `reply:{id}`, the link button when `consoleUrl` is set; Edit reply when there's a reply). Truncation to Discord's limits (embed description 4096, field 1024, total 6000, title 256; or the Components V2 text limits), always on a character boundary and marked with "…". Unit tests: every limit, a 1★ and a 5★, translated, no author, no device, a review containing `@everyone`.
4. **`src/jobs/send.ts`**: drain the outbox (V22) within the budget and the 60 s deadline (V23): claim, render from the current row, send, mark sent with the `messages` mapping (or retry / failed per V22.7). `review_new` and `connected` in this chunk; `message_update` and `review_edited` render through the same path but their final form is v1-5's. `index.ts` runs it after the poll.
5. **The look, in the test channel** (V41, V81):
   1. Post the same three or four real Lune reviews (a 1★, a 3★, a 5★ with a title, a translated one if available) **twice**: as classic embeds and as Components V2.
   2. The user picks the format, looking on desktop and mobile, light and dark theme.
   3. Iterate the details one question at a time: colour, title, which fields and in what order, the footer, relative time (`<t:…:R>`), the buttons, how a long review is cut.
   4. Remove the losing format's code. Write the **locked values** into the log.
   
   Confirm the v1-3 Copy rows with the user and mark them locked.
6. **The Reply button renders**, but clicking it fails in Discord until v1-4 (no endpoint yet). Tell the user that's expected.
7. **Integration tests** (Workers pool, `fetchMock` for Discord): pending rows sent oldest first with the Connected message first; the nonce on every create; a `429` stops the run and leaves the rest pending; a `500` backs off; a `400` fails the row; the budget stops the sender; a crash between send and mark (inject a failure in the mark) → the next run's create carries the same nonce; a backfill of 200 reviews drains over several runs within 45 calls each.
