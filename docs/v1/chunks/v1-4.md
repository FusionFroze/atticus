## In

1. **The replay-window question first.** Put the open item to the user (recommendation: reject timestamps more than 5 minutes from now). Record the answer.
2. **`src/notifiers/discord/verify.ts`**: Ed25519 over `timestamp + rawBody` with WebCrypto, the public key imported once per isolate. Tests with a key pair generated in the test: valid, tampered body, tampered timestamp, wrong key, missing headers, malformed hex.
3. **`src/notifiers/discord/interactions.ts`**: V50–V52. `POST /interactions` only. Verify before parsing. `PING` → `PONG`. Allow-list and channel checks with ephemeral refusals. `reply:{id}` → the modal (Label + paragraph Text Input, 350 max, prefilled for Edit reply). Unknown ids → ephemeral "not supported".
4. **`src/jobs/reply.ts`**: platform-agnostic. Given a review id, a user id and text: validate (1–350 after trim), call `ReviewSource.reply` (or the dry run, V55), write D1 in one batch on success, return a typed result. Logs `reply_published` / `reply_failed` / `reply_dry_run` / `reply_duplicate` with ids only.
5. **The submit path** (V53): validate → `DEFERRED_UPDATE_MESSAGE` → `waitUntil(reply job → edit the original through the interaction webhook)`; failures → an ephemeral follow-up (Copy). The message's new state: the reply shown, "Replied by" with the user and a relative time, the button now Edit reply.
6. **`fetch()`** in `index.ts` routes `/interactions`; everything else stays `404`.
7. **The modal and the replied message's look**, iterated with the user in the test channel (V81). Confirm the v1-4 Copy rows and mark them locked.
8. **Tests:** unit tests for verification and routing; integration tests (Workers pool) for each path: not allowed, wrong channel, unknown id, the modal for Reply and for Edit reply, a submit that succeeds (D1 written, the webhook PATCH sent), each failure kind (400, 403, 404, auth, 429, 5xx) → the right follow-up and no D1 change, the dry run (no Play call, no D1 change, the marker), text over 350.
