## In

1. **The `BACKFILL=summary` question first.** Put the open item to the user with the recommendation (drop it; keep `post` / `silent`). Record the answer; update `Config`, V1.md's open item (resolved) and `DECISIONS.md` accordingly.
2. **`src/core/review.ts`**: the `Review` type (the contract).
3. **`src/sources/play/normalize.ts`**: raw → `Review`. The title/body split on the first tab; `originalText` when translated; `deviceMetadata.productName` falling back to `device`; `androidOsVersion` → `osVersion` as a string; `developerComment` → `developerReply`; missing optional fields → `null` or `0`; a rating outside 1–5 or a missing `lastModified` → the review is skipped and logged (`review_malformed`), never a crash. `listRecent` now returns `Review[]`. Unit tests over fixtures for every case in `SPEC.md` §13 (no author, no device metadata, translated, with a developer reply, title with a tab, multi-page).
4. **`migrations/0001_init.sql`** from the Schema contract. Change a column only with a reason, recorded in the log. Add the D1 binding to both environments in `wrangler.jsonc` and the `db:migrate*` scripts.
5. **`src/store/`**: named functions for everything the jobs need, all multi-row writes in `batch()`:
   - read the stored rows for a set of review ids;
   - insert a review with its outbox row; update a review (edited, reply changed, reply removed) with its outbox row, applying V22's coalescing;
   - the lease (take, release; V24);
   - `state` get / set;
   - claim pending outbox rows (for v1-3), mark sent with the message mapping, mark retry / failed;
   - prune old outbox rows.
6. **`src/core/diff.ts`**: V32's table as a pure function, unit-tested row by row, including "own reply seen" vs "replied elsewhere" and "reply removed".
7. **`src/jobs/poll.ts`**: under the lease, for each app: `listRecent` → read stored rows → diff → write (V32) → first-run handling (V33: `app_seen`, the Connected outbox row with `sort_key = 0` and the count in its payload, `post` / `silent`) → `last_poll_at` → prune. `index.ts` calls it.
8. **Integration tests** (Workers pool, real local D1, `fetchMock` for Google):
   - first run, `post` and `silent`;
   - a second identical run → no new outbox rows;
   - an edit → `review_edited`; an edit while `review_new` is still pending → coalesced;
   - a reply appearing → `message_update` with `replied_via = 'external'`; our own reply text → nothing;
   - a reply removed → `message_update`;
   - two apps, one failing with 403 → the other still polled;
   - the lease held → `run_skipped_locked`, no writes.
