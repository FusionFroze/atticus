## In

1. **Tooling.** Ask the user to confirm the dev dependencies in V2 (one question, with versions). Then:
   - `package.json` (`"name": "atticus"`, `"private": true`, `"type": "module"`, version `0.1.0`, `engines.node` matching the current LTS), the scripts in the Contracts table (`db:*` may wait for v1-2).
   - `tsconfig.json` (strict, `noUncheckedIndexedAccess`, Workers types).
   - `biome.json` (formatter and linter; two-space indent, double quotes, semicolons; keep the rule set close to Biome's recommended).
   - `vitest.config.ts` with the Workers pool.
   - `wrangler.jsonc`: production at the top level and `env.dev` (V80), one cron (V30), `compatibility_date` set to today, `observability` logs on. No D1 binding yet (v1-2) unless it's simpler to add it now; record which.
   - `.dev.vars.example` listing every variable with placeholder values and a comment on where each comes from. Never real values.
2. **`src/config/`**: `parseConfig` per V10–V11 and the `Config` contract, with every error collected. Unit tests for each required var missing, each malformed value (bad snowflake, bad `APPS` JSON, unknown `APPS` field, duplicate app id, bad `consoleUrl`, bad timezone, bad `DIGEST_DAY` / `DIGEST_HOUR`, bad booleans, empty allow-list, malformed service-account JSON), and a test that no error message contains any part of a secret.
3. **`src/lib/`**: `log.ts` (structured JSON, V62), `budget.ts` (V23), `base64url` and PEM → PKCS#8 helpers.
4. **`src/sources/play/auth.ts`**: the service-account JWT (RS256, WebCrypto), the token exchange, the in-memory cache refreshed 5 minutes before expiry (V26). Failures map to `SourceFailure` `auth`. Unit tests with a throwaway test key generated in the test (never a real key): the JWT header and claims, the signature verifies with the public half, the cache reuses and refreshes.
5. **`src/sources/play/client.ts`** and **`types.ts`**: the raw API types (every field optional except what Google guarantees), `listReviews` with pagination (`maxResults=100`, `translationLanguage`, at most 5 pages, `truncated`), and status mapping to `SourceFailure`. Every call takes from the `Budget`. Tests with `fetchMock`: one page, three pages, the page cap, 401, 403, 429, 500, a network error, budget exhaustion. `reply()` is written here too (it's a small POST with the same error mapping) with its own tests, but nothing calls it until v1-4.
6. **`src/index.ts`**: `scheduled()` parses the config (on failure: `config_invalid` and return), builds the budget, lists each app's reviews and logs `poll_app` with the count, and **the review ids only**. `fetch()` returns `404` for everything (v1-4 adds `/interactions`).
7. **Fixtures.** Save one real page from Lune with the API (or hand-built if there are no reviews in the window), then **strip anything personal**: replace author names, review text and device details with invented values that keep the shape. Store it as `test/fixtures/play/page-1.json`. Confirm with the user before committing it.

## Verify

- `npm run check`: green.
- **Against Lune**, locally: `npm run dev`, then trigger the cron (`curl "http://localhost:8787/__scheduled?cron=*/15+*+*+*+*"` or the current wrangler equivalent). The log shows `token_refreshed`, `poll_app` with a plausible count, and only ids. A second trigger within the hour doesn't refresh the token (same isolate).
- **CPU:** if `atticus-dev` is deployed, `wrangler tail --env dev` shows the cron's CPU time for a cold run (with signing) and a warm one. Record both. If a cold run is near 10 ms, stop and raise V26's D1 cache question with the user.
- **Config errors:** remove `DISCORD_CHANNEL_ID` from `.dev.vars` and trigger: one `config_invalid` naming it. Corrupt the service-account JSON: the error names the field, shows no key material.
- **Logs are clean** (Smokes).
- `git status`: no `.dev.vars`, no key file, no real review content staged.
